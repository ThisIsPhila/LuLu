## Implemented

- Discoverable passkey registration/sign-in using SimpleWebAuthn, server signature verification and required device user verification. No in-app PIN simulation or timed success.
- Origin/RP binding, five-minute one-use challenges, request size limits and per-IP request buckets.
- Firebase custom-token sessions with server-side session records; twelve-hour maximum app session, ten-minute private step-up. Logout deletes session authority. Private exit/tab hiding clears private UI data and locks the server session.
- Owner-scoped realtime journal reads (latest 100), atomic saves and strict document schemas. Source fields/mappings cannot be added to display documents; protected titles must be generic.
- Separate AES-GCM encrypted original/title/entity payloads. Cloud private reads/writes require recent step-up. Device key stays non-extractable in IndexedDB; encryption binds account and record IDs.
- Encrypted trusted contacts: add/remove and explicit phone links; no automatic alert or messaging.
- No automatic upload or deletion of existing local records or demo seeds. Main app starts a signed-in account with its cloud records. Demo remains separate.

## Boundaries and pending work

The device key is not cryptographically derived from or wrapped by a passkey. Same-origin malicious code can still use it. Clearing browser data loses access to originals/contacts; original recovery and cross-device key transfer are not implemented. Ordinary journal text and transformed display text are readable by the backend; configured replacement rules do not guarantee removal of every identifying detail. General contextual AI recognition/processing is still pending. Entity edits currently apply to a session/new saves; catalogue recovery and reprocessing older entries remain pending. Some support/safety controls remain prototype content.

Native passkey creation/sign-in and the complete authenticated save/reopen journey require owner testing on the actual device. No passkey or user account was created by the agent. Live API checks confirmed registration options, required user verification, no-session401, foreign-origin403 and preflight204. This does not prove a successful Firebase token exchange or authenticated end-to-end journey.

The function deployment completed, but Firebase MCP reported failure to install the build-artifact cleanup policy. Runtime was independently checked. Artifact retention cleanup remains outstanding. No second backend region or additional paid service was provisioned as a workaround.
