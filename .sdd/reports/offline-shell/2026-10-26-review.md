# Offline shell prerequisite

Local working-tree implementation on 26 October 2026. Previous goal turn progressed implementation and test evidence; the full product goal remains active.

The app build generates a content-versioned service worker from its actual index, hashed JS/CSS/images and four local brand assets. Registration is production-app-only. Root/index navigation tries network then cached index; listed assets use cache-first. Methods other than GET, other origins, API/auth/data URLs, docs/demo/unknown navigation and unlisted assets bypass it. Runtime response caching is absent. External fonts are not precached. Main-only packaging is preserved.

Updates use the normal waiting lifecycle, without skipWaiting, clients.claim or forced reload. Cleanup touches only this app's cache prefix. A failed new install removes its own cache; a failed reinstall of an existing fingerprint retains that cache. This was specifically regression-tested.

Nine worker behavior tests and sixty existing ordinary/private tests pass (69 combined). Hosted build/main-only packaging, TypeScript and Firebase guard pass; existing chunk warning remains. Raw output in .sdd/evidence/offline-shell/. Browser check loaded the actual production app, stopped the local preview server, reloaded the root, then opened the fresh sign-in query route while the server remained stopped. Existing screens rendered; screenshot and procedure are recorded. No layout or controls were added. A later worker-only cleanup correction was rebuilt and regression-tested; it changes no rendered UI.

This is an offline startup prerequisite. Online server-verified sign-in and private step-up are unchanged; offline account authentication, private unlock and capture remain incomplete. Current random browser-held encryption key is not passkey-bound. A future offline capability must establish a prior online-verified device/account binding and fresh local cryptographic verification, separate from Firebase/server sessions; a new unprovisioned device cannot unlock existing account data offline. PRF support and target-device behavior remain to evaluate. No auth bypass is a fallback.

No deployment, cloud mutation, paid service, push or commit. Owner-native phone and design acceptance remain separate.
