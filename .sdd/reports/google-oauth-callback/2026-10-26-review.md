# Google OAuth callback correction

Date: 26 October 2026 (SAST)

## Live change

- Firebase Authentication for project `khora-lulu-2026` showed Google sign-in enabled and a web client ID matching the Google Cloud OAuth client.
- The app's configured `authDomain` is `khora-lulu-2026.web.app`. The OAuth client had only `https://khora-lulu-2026.firebaseapp.com/__/auth/handler` in its authorized redirect URI list.
- Added `https://khora-lulu-2026.web.app/__/auth/handler` to that same OAuth client. Read-back from Google Cloud showed both callback URIs saved. Existing JavaScript origins, the Firebase provider, client ID, and client secrets were not changed.
- A read-only Google Auth Platform branding check showed both `khora-lulu-2026.web.app` and `khora-lulu-2026.firebaseapp.com` in the OAuth consent screen's authorized-domain list.
- Opened the `.web.app` handler directly; it responded with Firebase's expected missing-initial-state message for a request without an OAuth session, rather than a missing-route response.

## Verification limits

- The live LuLu page on `lulu.thisisphila.co.za` displayed its existing-account sign-in and Google button. After starting Google sign-in in the in-app browser, the button remained at “Connecting to Google…”. The browser could not connect to `accounts.google.com` (`ERR_CONNECTION_CLOSED`) for a separate callback probe, so the Google authorization response and completed Firebase sign-in were not observed.
- Native bridge sign-in was not tested on a device. No app code, Hosting release, Firebase Auth provider settings, user accounts, project ownership, or billing settings were changed.
- This report records the console read-back; it does not claim end-to-end browser or native acceptance.
