# iOS startup repair — 26 October 2026

The owner reported a blank white screen in the installed iPhone app. It was reproduced on the physical iPhone 13 Pro Max (iOS 27.0.1) and the iPhone 18 Pro simulator (iOS 27.0). The native console confirmed the local WebView loaded and React's session-restoration effect read secure storage successfully, returning no pending exchange. Startup then stalled waiting for Firebase authentication initialization.

## Change

`src/services/backend/firebase.ts` now initializes native Firebase Auth explicitly, without the browser popup/redirect resolver. iOS uses Firebase's localStorage persistence with an in-memory fallback, following the existing Confessions implementation and its documented WKWebView IndexedDB auth-probe issue. Android keeps IndexedDB auth persistence. Native restoration waits for `auth.authStateReady()`. The web retains `getAuth()` and in-memory persistence.

The existing auth-restoration message now has a centered, safe-area-aware style so startup status remains visible. No new authentication screen was introduced.

Firebase session persistence here remains WebView-held storage, not Keychain protection. This change does not alter encrypted journal records, drafts, media, device-key storage, or record semantics. An existing iOS Firebase session held only by the prior IndexedDB configuration may require sign-in again; no journal data is deleted or migrated.

## Observed result

- App build, 24-file app-only package verification, Capacitor sync, and Firebase guard passed.
- Debug iOS simulator build and signed physical iPhone build passed.
- Updated app installed over the existing iPhone app without uninstalling or clearing data.
- Physical iPhone displayed the complete welcome screen after installation and again after terminating/relaunching the process.
- Simulator displayed the complete welcome screen after startup settled. Its screenshot taken eight seconds after launch was still black; this is not evidence of an eight-second startup guarantee.
- Temporary localhost preview of the same app bundle displayed the welcome copy and both entry buttons. Preview tab/server were closed afterward.

Raw observations, source hashes, and physical before/after screenshots are in `.sdd/evidence/ios-startup/`. The verification base was commit `9dd69fee75b744f68d0df6537f7bb91978476149` plus this change. Concurrent product/status documentation edits were preserved and excluded from this fix.

## Remaining acceptance

This verifies startup through onboarding, not authenticated journal persistence or provider acceptance. Firebase Auth provider configuration, hosted bridge, and Functions changes remain local/pending release. No Firebase deployment, push, IAM change, new signing identity, or new Apple team was performed. The existing development team signed the app already authorized for this iPhone.
