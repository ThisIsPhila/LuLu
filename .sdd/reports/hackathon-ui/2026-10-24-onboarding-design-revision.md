# Onboarding design revision — 24 October 2026

Owner rejected the first onboarding preview as low effort and misaligned with LuLu's design direction. The first version used repeated pale cards and CSS shapes, with too little of the brand kit's materiality or the product screen's editorial hierarchy.

The local preview at `docs/design/onboarding-auth/preview.html` was replaced with distinct welcome, orientation, passkey-creation, and returning-sign-in compositions. It uses the existing transparent LuLu logo exports, paper/sand/stone/charcoal palette from the brand kit, Literata-led headlines, original journal/stone photography generated for this project, a tactile access card, and more faithful spacing and material depth. The two-step orientation and screen navigation were observed working in the in-app browser. Passkey actions deliberately show a preview-only notice; no false authentication transition is present.

Evidence captures in `.sdd/evidence/hackathon-ui/`: `onboarding-welcome-revised.png`, `onboarding-orientation-revised.png`, `onboarding-create-revised.png`, and `onboarding-signin-revised.png`. The browser preview was checked at a desktop viewport with a 410px mobile canvas. Physical device and keyboard testing remain outstanding. The mobile CSS fills the viewport with safe-area spacing; narrow physical device behavior has not been independently observed. No backend, account, database, or protected-mode integration was changed. Owner visual acceptance is pending.

Further owner correction: use a library for available elements and icons. Removed the hand-drawn phone hardware, passkey credential illustration, and CSS key icon. The preview now renders arrows and a key through the existing `lucide-react` package, uses a native `progress` control, and uses project photography for the create-access image. Reviewed 21st.dev passkey and phone components; the available passkey example is AGPL-3.0 with a password fallback, while a suitable MIT phone candidate is an auto-rotating screenshot carousel. Neither was copied. Visual browser checks confirmed the Lucide key and arrow icons render. The revised preview remains a design, not an auth implementation.
