# Private media capture and reopening

Local working-tree implementation, 26 October 2026. Full product goal remains active. The previous turn progressed implementation/evidence; no completion claim for the whole application.

Private sessions now instantiate LocalMediaVault with the same account, live unlock and generation boundary as private text. The existing private writing card hosts the image/microphone tool pattern already used in the composer; no new destination, sidebar, page layout or CSS was introduced. Image uses a native file input with environment-camera hint. Microphone explicitly requests audio, negotiates browser MIME support, stops once and saves browser-encoded bytes. The ordinary editor's existing image/mic affordances now explain how to enter private capture instead of silently doing nothing; ordinary attachment storage remains open.

Media are independent immutable originals, not attachments to text revisions. Raw bytes and metadata have separate AES-GCM envelopes under the existing browser-held nonextractable key, bound to owner/media ID. SHA-256 and byte length are authenticated on read. Metadata/binary are added in one IndexedDB transaction; duplicate IDs cannot overwrite. v1 combined rows migrate to v2 split stores. Lists load only encrypted metadata rows, not all ciphertexts. 25 MiB is checked before file read. MIME allowlisting excludes SVG/HTML/video; it does not attest actual file format, source provenance or browser codec support.

Private media list/detail reuses existing record-row/detail styles. Media remain concealed until Reveal; audio never autoplays. Conceal/back/exit/unmount remove media, pause a captured playback-node reference, revoke object URLs and invalidate delayed callbacks. Capture cleanup stops tracks, drops chunks/timers and ignores late permission results. The recorder schedules stop at60 seconds; elapsed duration is an approximation using a monotonic clock and is not falsely clamped if the browser delays the timer. Oversize/failed recordings are discarded with a content-free status. Failed storage retains the capture for explicit retry only while the page/session remains open; exact lost-acknowledgement reconciliation prevents duplicate originals. Sudden browser/power failure before commit cannot guarantee recovery of unsaved media.

Verification: 93 focused device-key/media/recorder/ordinary/private/offline tests pass; hosted build/main-only packaging and Firebase guard pass. Tests include exact binary/chunk preservation, metadata privacy, tampering/owner swaps, duplicate races, generation/lock rejection, migration, list memory boundaries, transaction rollback on quota/setup failure, late microphone permission, cancel/stop/error/size/time handling. Quota regression verifies no orphan metadata/binary and preserves an existing record. Raw TAP, final build and source hashes: .sdd/evidence/private-media/.

Actual-component synthetic browser flow verified picker→encrypted save→list→reload→metadata-only reopen→reveal→conceal→quick exit. Decoded synthetic PNG width1; zero blob media elements after conceal/exit. Native camera/microphone, actual codec/playback, authenticated cloud app integration, target phone keyboard and design acceptance remain pending. No new user credential, real camera/microphone capture, cloud transport, paid service, deploy, commit or push.

The key is still browser-held, not cryptographically passkey-bound. Offline startup prerequisite exists, but offline authentication/unlock/capture after reload remains open. Media caption/revision association, ordinary attachments, readable export, deletion, encrypted backup/recovery and phone acceptance remain on the tracker.

Primary API behavior checked: [MDN capture attribute](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture) describes an optional camera hint with limited availability; [MediaRecorder stop event](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/stop_event) specifies final dataavailable before stop, which the controller retains. No camera attestation or universal platform support is inferred.
