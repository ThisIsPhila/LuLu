# Ordinary saved-entry actions review

Date: 26 October 2026 (SAST). Environment: local source tree and local Firestore emulator; no live Firebase data, deployment, or device acceptance.

## Implemented

- The existing composer More/Options affordance selects Journal or Story for new entries and edits. Editing preserves the Firestore document ID and writes the selected kind through the existing ordinary update path.
- Awaited save/delete completion is guarded by a committed compose-route identity and current account session, so an operation started on an older route cannot clear or redirect a newer editor.
- An ordinary saved entry can be exported on explicit download as `lulu-ordinary-entry.json`. The JSON contains only ID, saved title/body, kind, date, and optional tags. It excludes protected originals/entities and unrelated entry fields; unsaved edits are not included.
- An ordinary entry can be permanently deleted only after the inline scope warning, acknowledgement checkbox, and distinct confirmation button. The backend rejects invalid IDs, mismatched owners, protected records, missing records, and Firestore denials. The selected document alone is deleted; starter initialization marker behavior prevents deleted starters from returning.
- No private local record, private collection, page, navigation, CSS, or cloud lifecycle flow is added.
