# Curated Story reading sequence review

**Date:** 26 October 2026, SAST  
**Scope:** Connect saved Story collections to continuous reading in the existing Reader.

When a Story source is opened from Stories, the view now supplies the complete matching ordinary collection. A pure domain helper filters to ordinary Story records and sorts them by saved timestamp, oldest first, with stable ID ordering for ties. The Reader shows the collection name, an accessible part count and Previous/Next controls only for groups with more than one entry. Each step changes the selected source record, preserves its own title/body/date and returns to the Stories route through the existing Back behavior. Entry changes reset scroll to the top. No side panel, separate reader, generated content or storage schema was added.

Five focused ordinary-browse tests pass, including chronological ordering and exclusion of protected and Journal records; `npm run build:app` passes. Local seeded UI navigation Stories → Reader → Stories was observed with a single Story, so the multi-entry controls remain unverified in a rendered browser session. No Firebase rule deployment, working-site/device acceptance, or owner visual acceptance is claimed. Vite reports one generated JavaScript chunk above 500 kB; build/package verification succeeds.
