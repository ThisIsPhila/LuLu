# Local private deletion and recovery-file primitive

26 October2026 · local only · broader product goal remains active.

Deletion is integrated beside export in existing private record detail, with scoped counts, an acknowledgement checkbox and a distinct permanent-delete action. No new page/sidebar/CSS. Current unsaved editor changes gate deletion until saved/reopened. Cancel/exit release the prepared plan; unknown acknowledgements ask for a refresh instead of falsely promising no deletion.

Text deletion authenticates a snapshot of original/revisions/linked recoverydrafts, then compares the current encrypted snapshot and deletes head/history/linked drafts in one transaction. Changed history/draft sets/envelopes abort. Media deletes its metadata/binary pair atomically; preparation reads metadata only. Other owners/records/unlinked drafts/keys/cloud/downloaded copies remain outside scope. Plans are one-shot and bound to live account/session generation.

Targeted autosaves verify the parent record/revision still exist inside the same write transaction, preventing queued drafts from resurrecting a deleted record. Review removed an unnecessary latest-parent restriction: edits against an existing historical revision remain recoverable, while finalization still rejects stale parents. Regression covers both cases.

Recovery-file encryption primitive is implemented/tested but intentionally not offered as a backup product yet. It encrypts arbitrary bounded bytes using a fresh16-byte salt, PBKDF2-SHA256(600000 iterations), nonextractable AES256-GCM key, fresh12-byte IV and authenticated binary header. Fixed KDF/file-size bounds reject hostile parameters; wrong passphrases/header/body tampering fail; live-authorization callbacks gate async results. Payload limit64MiB. Passphrase is preserved exactly, not normalized/trimmed. This is not vault restore or device-key recovery; full backup/restore integration is next and must prove original metadata/history preservation and conflict-safe fresh-device import before exposure.

Primary API references: [WebCrypto deriveKey](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveKey), [AES-GCM parameters](https://developer.mozilla.org/en-US/docs/Web/API/AesGcmParams). No independent security audit or universal phone-performance claim.
