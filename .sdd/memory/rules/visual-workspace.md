# Visual workspace agent operation

Canonical intent/status lives in `.sdd`: requirements → design → tasks → evidence. The browser is a derived read-only view. Use phase.sh lifecycle/task commands; never maintain separate UI task state. Record evidence with source revision, procedure, environment and result. Hooks run on commits; configured hooks and observed gate runs are different facts.

With the framework clone's optional visual package installed/built, launch `npm --prefix /path/to/framework/visual run workspace -- --project /absolute/project`. The local launch token stays private. No account is needed. Updates appear automatically while the service runs; start the service before giving a user its URL and check it responds. Do not claim running from a successful build alone.

At successful phase finish, graph-refresh.cjs generates `.sdd/graphs/framework.json` if Node is available. It extracts declarations/references without inference. If skipped/failed, report that and run `node .sdd/scripts/graph-refresh.cjs .` when available. Imported Graphify exports are separate and are not regenerated by this command. Rerun the external tool only when explicitly authorized. Read graph provenance; references do not establish fulfillment. Missing phase dependencies mean unknown, not independent.

For existing projects use setup.sh --upgrade conservatively. Preserve specifications, memory, custom rules, skills and hooks; review the upgrade manifest and run doctor. Existing onboarding files are preserved, so explicitly read this new rule after upgrading. Agents need filesystem/CLI access, not mandatory browser access.
